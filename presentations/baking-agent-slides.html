03｜Graph 主流程

將工作拆成可檢查節點

PLAN → SEARCH → FETCH → SOURCE_GATE → PARSE → NORMALIZE → SCHEMA_CHECK → REPAIR → REASONING_CHECK → DOC_CONSISTENCY_CHECK → DEDUPLICATE → PERSIST → REPORT

各節點更新共享 State；條件邊決定成功、重試、待確認或人工審查的下一步。

04｜Loop／錯誤分支

資料有問題時，不要自行猜測

  • SOURCE_GATE 失敗：回 SEARCH 更換來源，重試最多 2 次。
  • SCHEMA_CHECK 失敗：有來源依據的格式錯誤進 REPAIR；原始資料不足則回 FETCH。
  • REASONING_CHECK：檢查材料與步驟、時間、溫度、設備、過敏原及安全。
  • DOC_CONSISTENCY_CHECK：比對 Wiki 與 HTML；不一致就修正簡報並重查。
  • WARNING：進待確認區；FAIL 或重試超限則交人工審查。

最嚴重的是跨文件配方錯置

RCP-005

原簡報標示免揉麵包，卻混入另一份配方的糖、溫水、揉麵及 450°F 操作。

已按 Sally's Baking 來源改回 430 g 麵粉、6 g 酵母、9 g 粗鹽、360 ml 偏涼水及 475°F。

RCP-004

步驟有一小撮鹽，但材料表漏列；來源 65 分鐘未含完全冷卻與糖霜作業。

RCP-003

蛋糕本體不含奶蛋，但原始糖霜含 half-and-half，需明確分開。

07｜反思

最常出錯的節點：REASONING_CHECK

資料欄位即使都存在，仍可能有內容矛盾。RCP-005 的錯置就是材料表與步驟看起來完整，卻不屬於指定來源。

  • 材料表與步驟雙向核對。
  • 官方總時間與分段時間交叉計算，冷卻及裝飾另列。
  • 飲食標籤拆成蛋糕本體、糖霜與市售替代品查核。
  • 新增 DOC_CONSISTENCY_CHECK，比對 Markdown／HTML 的來源、材料、烤溫、時間及狀態。
