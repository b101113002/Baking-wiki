04｜例外處理與重試

每種錯誤都有明確出口

01來源讀取失敗

SOURCE_GATE FAIL→SEARCH → FETCH

更換候選來源再讀取；累計重試最多 2 次，超限轉人工審查。

上限 2 次

02欄位與格式問題

格式可修→REPAIR→SCHEMA_CHECK

缺原始資料則回 FETCH／SEARCH；核心材料或步驟無法確認，不可自行補值。

修正重查最多 2 次

03內容合理性與安全

PASS → DOC_CHECKWARNING → QUARANTINE

可由來源釐清的矛盾回 FETCH；FAIL 或重大安全疑慮交由人工審查。

04Wiki／HTML 不一致

MISMATCH→REPAIR_PRESENTATION→重查

以已核准的 Wiki 資料修正 HTML；比較工具未接通或證據不足時只能標記 WARNING。

修正重查最多 2 次

05重複資料判斷

相似項目→DUPLICATE_REVIEW

可新增／新版本才保存；確認重複則略過；版本差異不明時交由人工決定。

06正式資料寫入失敗

PERSIST FAIL→重試→REPORT

只有 GitHub 回報成功才更新保存紀錄；重試耗盡後交由人工審查。

寫入重試最多 2 次
QUARANTINE 與 HUMAN_REVIEW 最後都會進入 REPORT，保留完整結果與錯誤紀錄。
05｜本次實際發現

最嚴重的是跨文件配方錯置

RCP-005

原簡報標示免揉麵包，卻混入另一份配方的糖、溫水、揉麵及 450°F 操作。

已按 Sally's Baking 來源改回 430 g 麵粉、6 g 酵母、9 g 粗鹽、360 ml 偏涼水及 475°F。

RCP-004

步驟有一小撮鹽，但材料表漏列；來源 65 分鐘未含完全冷卻與糖霜作業。

RCP-003

蛋糕本體不含奶蛋，但原始糖霜含 half-and-half，需明確分開。

07｜反思

最常出錯的節點：REASONING_CHECK

資料欄位即使都存在，仍可能有內容矛盾。RCP-005 的錯置就是材料表與步驟看起來完整，卻不屬於指定來源。

  • 材料表與步驟雙向核對。
  • 官方總時間與分段時間交叉計算，冷卻及裝飾另列。
  • 飲食標籤拆成蛋糕本體、糖霜與市售替代品查核。
  • 新增 DOC_CONSISTENCY_CHECK，比對 Markdown／HTML 的來源、材料、烤溫、時間及狀態。

08｜限制與下一步

  • GitHub Pages 部署狀態仍需在 Repository Settings → Pages 確認。
